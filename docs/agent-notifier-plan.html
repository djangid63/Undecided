Agent notifier: 6-week build plan

Electron shell, Node daemon, Claude Code and Codex adapters, phone approval. Ten milestones in six weeks, each with one runnable deliverable and a security gate before you move on. About 3.5 hours a day, 6 days a week.

Ground rules

  • One session ends with one thing that runs. Never stop mid-step.
  • Explain each milestone's code back in your own words and fix the gaps before moving on.
  • A milestone isn't done until its security gate is checked.
  • Commit and push daily, and add one line per session to LOG.md, starting with the date (2026-10-20).
  • When a milestone's gate passes, add a line DONE M<n> to LOG.md (for example DONE M0). The daily schedule check reads it.
  • The 7th day each week is a buffer for catching up or resting. It is never a reason to skip a gate.
  • If you slip more than 2 days, move the start date so the whole plan moves. Never squeeze milestones 6 and 8.

Daily session (3.5 h)

15 minRead yesterday's LOG.md line; re-run the last check command
2.5 hBuild: type it, run it, fix it
30 minExplain it back: 3 to 5 lines in your own words
15 minCommit, push, one line in LOG.md

Bad day? Do 1.5 hours, not zero.

Notes

  • Milestones 6 and 8 carry the most risk (approval logic, then remote auth). They fall in calendar weeks 4 and 5. Add buffer there rather than rushing.
  • The last two days of week 6 are a final buffer before the plan ends.
  • If you fall behind, cut in this order: your own character and art (move to after release), then phone UI polish. Never cut a security gate or the explain-back step.
  • The milestone 9 threat model is a portfolio piece on its own.
  • Codex support changes quickly. Check the current Codex docs before the milestone 3 spike and the milestone 5 adapter, and confirm whether its permission hook can return a decision or only observe.
  • Coucou is reference only. Before going public, confirm no code or assets from it remain in the repo.
